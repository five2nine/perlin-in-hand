# Camera, Object, World Viewing

## 목적

3D 화면을 볼 때 사용자는 화면에서 무언가가 회전하는 것을 본다. 이때 실제로 움직인 것이 카메라인지, 단일 오브젝트인지, 월드 전체인지, 빛인지가 곧바로 구분되지 않는다. 이 문서는 terrain generator와 viewer를 만들면서 생긴 논의를 정리한다.

핵심 질문은 다음이다.

- 대상은 단일 오브젝트인가, 여러 물체가 들어 있는 월드인가?
- 사용자의 조작은 카메라를 움직이는가, 오브젝트를 회전시키는가?
- 빛은 월드에 고정되어 있는가, 카메라에 붙어 있는가?
- 화면에서 보이는 회전 인상만으로 실제 변환을 구분할 수 있는가?

## 네 가지 기준 좌표계

3D 장면은 보통 다음 좌표계를 함께 사용한다.

| 기준 | 의미 | 코드에서 흔한 이름 |
| --- | --- | --- |
| Object / Model | 개별 물체의 로컬 좌표 | `model_matrix`, transform, rotation |
| World | 여러 물체가 놓이는 공통 공간 | world position, scene graph |
| Camera / View | 사용자가 보는 위치와 방향 | `view_matrix`, `camera.matrix`, lookAt |
| Light | 조명의 위치와 방향 | `light_pos`, directional light |

화면의 최종 위치는 대개 `projection * view * model * position` 순서로 계산된다. 여기서 `model`이 바뀌면 물체가 움직이고, `view`가 바뀌면 카메라가 움직인다. 둘 다 화면에서는 비슷하게 회전처럼 보일 수 있다.

## 현재 terrain 계열의 해석

현재 GPU terrain generator, sphere generator, GPU viewer는 기본적으로 카메라 orbit 방식이다.

- `model_matrix`는 항등행렬로 유지한다.
- 마우스 드래그는 `camera.angle_x`, `camera.angle_y`를 바꾼다.
- 셰이더는 `m_proj * m_view * m_model * world_pos`로 그린다.
- 빛 위치는 uniform으로 전달되며, terrain 계열에서는 월드 좌표의 고정 위치처럼 쓰인다.

따라서 현재 terrain 화면에서 지형이나 구가 직접 회전하는 것이 아니다. 오브젝트와 빛은 월드 안에 놓여 있고, 카메라가 대상 주위를 돌며 본다.

## 카메라 회전과 물체 회전이 비슷하게 보이는 이유

단일 오브젝트만 화면에 있을 때는 카메라 orbit과 물체 회전이 매우 비슷하게 보인다. 구, 병, 조각상, 단일 terrain mesh처럼 주변 기준물이 적은 대상은 더 그렇다.

카메라가 오른쪽으로 이동해 물체를 보는 것과, 물체가 왼쪽으로 회전하는 것은 화면 위의 실루엣 변화가 서로 닮는다. 이 때문에 사용자는 "내가 물체 주위를 돈다"와 "물체를 손으로 돌린다"를 감각적으로 섞어 받아들이기 쉽다.

구분 단서는 조명과 기준물이다.

| 상황 | 화면에서 보이는 특징 |
| --- | --- |
| 카메라가 회전하고 빛은 월드 고정 | 밝은 방향이 월드 기준으로 유지되고, specular/rim은 보는 방향에 따라 바뀐다. |
| 물체가 회전하고 빛은 월드 고정 | 물체 표면의 normal이 빛에 대해 달라지므로 밝고 어두운 부분이 물체 표면 위에서 이동한다. |
| 카메라가 회전하고 빛도 카메라에 붙음 | 화면 기준으로 조명이 따라오므로 물체 회전과 매우 비슷하게 느껴진다. |
| 월드 전체가 회전 | 여러 오브젝트가 한 덩어리처럼 움직인다. 월드 고정 기준물이 없으면 카메라 회전과 구분하기 어렵다. |

## 빛이 카메라에 붙어 있을 때

며칠 전에 만든 지구본식 화면처럼 카메라가 실제로 움직이고 있어도, 빛이 카메라에 붙어 있으면 물체가 회전하는 것과 비슷한 효과가 난다.

이 조합에서는 사용자가 눈으로만 보고 실제 변환을 확정하기 어렵다.

- 카메라는 공전한다.
- 빛은 카메라와 함께 움직인다.
- 오브젝트는 정지한다.

그런데 화면에서는 항상 보는 쪽에서 빛이 비치는 것처럼 보인다. 그래서 지구본을 실제로 돌린 것인지, 카메라가 돌면서 조명도 따라온 것인지 감각만으로 분리하기 어렵다.

## 대상이 월드일 때

terrain, 빌딩, 산, 나무, 태양, 하늘처럼 여러 요소가 있는 장면은 월드가 기준이다. 이때는 카메라가 이동하는 방식이 자연스럽다.

낮 풍경을 만든 경우 태양과 지형, 건물은 월드 안에 고정되어 있고, 사용자는 걷거나 날거나 차를 타고 이동하듯 장면을 본다. 이 장면에서 물체들을 직접 돌리면 풍경 전체가 장난감처럼 느껴질 수 있다.

월드 탐색에는 다음 방식이 어울린다.

- orbit camera: 특정 대상 주위를 도는 감상 모드
- fly camera: 공간을 자유롭게 날아다니는 모드
- walk / drive camera: 사람이나 차량처럼 이동하는 모드
- cinematic camera: 미리 정한 경로와 시선을 따라 움직이는 모드

## 대상이 단일 오브젝트일 때

단일 오브젝트를 감상하는 화면에서도 카메라 orbit이 흔하다. 제품 뷰어, 조각상, 3D asset preview, 유리병 안에 놓인 물체를 보는 데모가 여기에 들어간다.

이때 사용감은 "물체를 돌려본다"에 가깝지만, 구현은 카메라가 물체를 바라보며 주변을 도는 방식일 수 있다. 카메라 orbit은 나중에 단일 오브젝트가 복잡한 월드로 확장될 때도 같은 기준을 유지하기 쉽다.

물체 자체를 돌리는 방식도 널리 쓰인다. CAD, 모델링 툴, 캐릭터 preview, turntable render에서는 오브젝트나 부모 노드를 회전시키는 편이 단순하고 실용적이다. 이 방식은 "세계 안의 물리 장면"보다 "물체 형태 검사"에 더 가깝다.

## 여러 오브젝트가 있을 때

월드 안에 오브젝트가 여러 개 있으면 구분 단서가 늘어난다.

- 카메라가 회전하면 모든 물체가 화면에서 함께 움직이지만, 월드 안의 배치와 거리 관계는 유지된다.
- 특정 물체가 회전하면 그 물체의 표면 무늬, normal, 조명 반응만 바뀐다.
- 월드 전체가 회전하면 여러 물체가 한 덩어리처럼 움직인다.
- 빛이 카메라에 붙으면 조명 단서가 줄어든다.

그래서 여러 오브젝트 장면에서는 바닥 그리드, 월드 축, 고정된 작은 마커, 태양 위치 표시 같은 기준물이 큰 도움이 된다.

## 구분을 위한 실용 표식

화면만 보고 구분하기 어려운 경우 다음 표식을 두면 좋다.

- 월드 좌표축: X/Y/Z 방향을 고정 표시한다.
- 바닥 그리드: 월드가 고정되어 있는지 알 수 있다.
- light marker: 태양이나 점광원 위치를 작은 구체나 아이콘으로 표시한다.
- orientation gizmo: 카메라 기준에서 월드 축이 어떻게 보이는지 보여준다.
- surface marker: 구면 terrain의 북극, 경도 0도, 경도 90도처럼 물체 표면의 기준점을 표시한다.
- UI 표시: `Camera Orbit`, `Object Rotate`, `World Light`, `Camera Light` 같은 현재 모드를 표시한다.

스피어 terrain의 오른쪽 상단 표시기는 이런 표식의 한 예다. 그 표시기는 지형 미니맵이 아니라, 현재 카메라에서 구면 좌표 기준이 어떻게 보이는지 알려주는 orientation gizmo다.

## 설계 판단

3D 화면에서 다이내믹한 인상을 만드는 기본 수단은 대체로 카메라 이동과 시점 전환이다. 단일 오브젝트 감상, terrain viewer, 월드 탐색은 모두 카메라를 움직이는 방식으로 자연스럽게 연결된다.

다만 단일 물체 검사 화면과 turntable 데모에서는 물체 회전도 합리적인 선택이다. 선택 기준은 다음처럼 잡을 수 있다.

| 목적 | 권장 방식 |
| --- | --- |
| terrain, 도시, 자연 풍경 탐색 | 카메라 이동, 월드/태양 고정 |
| 단일 오브젝트 감상 | 카메라 orbit 우선, 필요할 때 object turntable |
| 제품이나 asset의 형태 검사 | object rotate 또는 orbit camera 모두 가능 |
| 물리적으로 일관된 낮 풍경 | 카메라 이동, 월드 light 고정 |
| 화면 기준으로 항상 보기 좋은 데모 | camera light 또는 보조 fill light 사용 가능 |

terrain generator와 viewer는 월드와 지형, 빛의 관계를 읽는 도구다. 그래서 현재 구조처럼 지형은 고정하고 카메라가 움직이는 방식이 적절하다. 스피어 terrain도 같은 이유로 카메라 orbit을 기본으로 두고, 좌표 표시기와 light marker 같은 보조 표식을 추가하는 방향이 좋다.
